# Task Plan — 從教材／需求規劃出 TODO 任務

流程：**定範圍 → 盤點現況 → 找資料並登記 → 讀資料、寫摘要 → 差距表 → 切任務 → 寫進 TODO.md → 回報、交 task-next**。
產出物有三個：`doc/reference/<主題>.md`（摘要＋差距表＋建議功能）、`doc/reference/README.md` 登記、`TODO.md` 新任務。
全程用繁體中文。

**專案設定從哪來**：專案 `CLAUDE.md` 的 `## task-workflow 設定`（參考資料索引、掃描 PDF 頁碼對照、資料慣例、主程式檔）。找不到這一節就先停下請使用者補。

---

## 🚨 硬規則

1. **不碰主程式檔**：規劃階段只改 `TODO.md`、`doc/reference/*.md`、`doc/reference/README.md`。要改程式請走 `task-next`。
2. **任務指向摘要，不指向 PDF**：TODO 每一項的依據寫 `doc/reference/<主題>.md` 與頁碼標記（`[S 279–281]`），不寫 PDF 路徑或 PDF 頁數。
3. **摘要用自己的話，標頁碼**：原始教材不進 git，摘要不逐字抄錄；每個結論後面標 `[代號 頁碼]`。頁碼以頁面上印的為準，不是 PDF 頁序。
4. **先盤點再規劃**：沒看過現況（程式有哪些功能、TODO 已有哪些項、decisions 定過什麼）不寫差距表。否則會規劃出已經做好的功能或撞上已推翻的決定。
5. **寫進 TODO.md 前先給使用者看**：差距表與任務清單先貼給使用者，點頭後才動 `TODO.md`。授權批次模式（使用者明說「由你規劃、我不介入」）可以直接寫，但要在回報裡列出全部新項目。
6. **主 session 用量守六成**：讀掃描 PDF 很吃 context，轉圖與讀圖派 subagent（附錄 A）；主 session 只收摘要。

---

## 步驟 0 — 定範圍

先把三件事講清楚再開工（一句話各一行，貼給使用者）：

```
▶ 規劃範圍
【主題】<例：教科書 Ch8／Ch9 策略矩陣分析的完整引導>
【來源】<代號與章節／頁範圍，或「使用者需求：…」「ST-05 驗證時發現的三個問題」>
【對照對象】<專案 分支 commit，例：main 139dee9（2026-10-25 盤點）>
【輸出】doc/reference/<主題>.md ＋ TODO.md <前綴>-NN 系列
```

來源分三類，處理深度不同：
| 來源 | 要不要寫摘要檔 | 說明 |
|---|---|---|
| 教科書／講義／備忘（有頁碼） | 要 | 走完整流程（步驟 2–6） |
| 使用者口頭需求、截圖 | 不用，直接切任務 | 跳到步驟 5；圖片用 Read 看過 |
| 驗證時冒出的問題清單 | 不用 | 跳到步驟 5，每個問題一項，註明「XX-NN 驗證時發現」 |

## 步驟 1 — 盤點現況

```bash
cat TODO.md
cat doc/decisions.md
ls doc/reference/ && cat doc/reference/README.md
git log --oneline -15
```

- 已做的功能：從 TODO.md `[x]` 與 Complete 區拉清單，不必重看程式。
- 程式現況：派 `Explore`（"medium"）問 3–5 個具體問題——「有沒有 X 功能」「資料存在哪個結構、key 怎麼取」「匯出有沒有對應頁」。**不要整份讀主程式檔。**
- 已定的決定：`doc/decisions.md` 裡跟本主題相關的條目抄進步驟 4 的「限制」，避免規劃出被推翻的做法。
- 同主題已有摘要檔 → 在那份上追加章節，不另開新檔。

---

## 步驟 2 — 找資料並登記

1. 先讀設定裡的參考資料索引（預設 `doc/reference/README.md`）：代號、檔案位置、頁數、已摘要欄。
2. 本機找得到的直接用路徑；找不到的（老師雲端分享的 `.lnk` 捷徑等）用 Google Drive 連接器 `title contains '關鍵字'` 搜，資料夾 ID 記在索引裡。
3. **新來源先在索引登記**：表格加一列（代號、檔案、頁數、已摘要「—」），代號沿用既有規則（教科書 `S`、講義 `P1`～`P4`、備忘 `M月日`）。
4. 掃描 PDF 先確認頁碼對照（PDF 第 n 頁 ＝ 書上第幾頁），寫進索引的規則區；沒有就抽兩頁核對後補上。

---

## 步驟 3 — 讀資料、寫摘要

讀法見附錄 A（掃描 PDF 轉圖、派 subagent 讀）。摘要檔 `doc/reference/<主題>.md` 固定開頭：

```
# <主題>

- 來源：<書名／講義 章節、頁範圍>。頁碼標記 `[代號 頁]`。
- 對照對象：<專案 分支 commit（日期）>。
- 用途：作為 TODO.md <前綴>-NN 系列的規劃依據。內容為摘要，不逐字抄錄。
```

摘要要抓的東西（對做功能最有用的，依序）：
- **流程／步驟**：教材的做事順序，之後直接變成差距表的列。
- **定義與分類**：之後要做成程式常數的（如 51 項要素、六列意義、前提類型）——整表列出並標頁碼。
- **規則**：「某形狀→建議某項」「某情況視為某類」這種可自動化的判斷，列成表。
- **範例**：書上的完整實例（公司、欄數、圖號、頁範圍），之後可做範例專案或測試資料。
- **引導問題**：教材的提問可改寫成 UI 文案，用自己的話，標頁碼。

不要摘的：背景敘述、與功能無關的論證。

---

## 步驟 4 — 差距表（核心產出）

摘要檔加一節「教材 vs 現況」，一列一步驟：

```
| # | 教材步驟 | 出處 | 現況 | 缺口 |
|---|---|---|---|---|
| 1 | <教材做什麼> | Ch8 §1 [S 270–275] | ✅ 已有 <功能> | <還差什麼，具體到元件> |
| 2 | ... | ... | ⚠️ 部分：<有什麼沒什麼> | ... |
| 3 | ... | ... | ❌ 沒有 | ... |
```

- 現況只寫三種：✅ 已有、⚠️ 部分、❌ 沒有；判斷來自步驟 1 的盤點，不猜。
- 缺口要寫到「做出來會是什麼元件」（面板、下拉、常數表、匯出頁），不寫「要加強」。
- 表後補一節「貫穿全程的缺口」：不屬於單一步驟、但整體缺的東西（例：沒有流程導引、沒有範例）。
- 再加一節「實作注意事項」：從 decisions.md 與資料慣例抄來的限制（例：用「欄 id＋列字母」當 key、舊存檔要能載），之後每個任務的【限制】都從這裡引。

---

## 步驟 5 — 切任務

把缺口變成任務，規則：

1. **一個缺口一個主任務**；主任務下再依「資料結構／UI／匯出／範本資料」切子任務（a、b、c…），每個子任務一個 worker 做得完（經驗：讀外部資料＋改 300 行以上就要切）。
2. **分階段排序**，寫在摘要檔「建議功能清單」一節，依序：
   - 第 1 階段：核心、低風險、別的都依賴它（例：資料欄位、基本面板）
   - 第 2 階段：導引與範例（讓使用者看得到成果）
   - 第 3 階段：進階分析（依賴第 1 階段資料）
   - 第 4 階段：執行面與匯出（最後做，格式才會定）
   - 文件／手冊更新放各階段末或最後一項
3. **每項任務一行寫完**（TODO.md 格式）：
   ```
   - [ ] XX-NN <動詞開頭的標題>：<做什麼（元件、欄位、規則）>；<內建資料或範例> [代號 頁碼]
   ```
   帶條件的補縮排子彈：「已定：…」「不做：…」「依賴 XX-MM」。
4. **主任務頭加一行「規劃依據」**指向摘要檔：`規劃依據與頁碼見 doc/reference/<主題>.md`。
5. **共通限制只寫一次**在主任務下的「已定」子彈（例：key 慣例、舊存檔相容），子任務不重抄。
6. 大主題（≥ 8 個子任務）用「第 N 階段：<名稱>」的純文字列把子任務分組，方便批次模式一波一階段。

切完先給使用者看（硬規則 5）：

```
▶ 規劃結果：<主題>
摘要檔：doc/reference/<主題>.md（<N> 節）
差距表：<M> 步，✅ a／⚠️ b／❌ c
新任務：<前綴>-NN 主任務 <K> 項、子任務 <J> 項，分 <P> 階段
  第 1 階段：XX-NNa、XX-NNb …
  第 2 階段：…
相依：<哪些要先做>
要決定的點：<最多 3 個，各附建議>
```

---

## 步驟 6 — 寫進 TODO.md

使用者點頭後：
1. 先掃一遍 `TODO.md` 把沒編號的補上（規則同 task-next 步驟 1：前綴沿用、取最大號＋1）。
2. 新主任務接在該區最後一個未完成項之後；子任務縮排兩格。
3. `git diff TODO.md` 貼給使用者。
4. 摘要檔在索引 `README.md` 的「已摘要」欄登記檔名與涵蓋頁範圍。
5. commit（只含 `TODO.md`、`doc/reference/*`）：
   ```
   規劃 <前綴>-NN <主題>：摘要 doc/reference/<主題>.md、差距表、<K> 主任務 <J> 子任務
   ```
   在 `dev` 分出的 worktree 上做；若目前在 `main` 先停下問使用者。

---

## 步驟 7 — 回報、交 task-next

回報：摘要檔路徑、commit、新任務代號清單、建議第一個做哪項、哪些要先問使用者。
然後停下。使用者說「下一步」或「開第 1 波」才由 `task-next` 接手派工。

## 附錄 A — 讀掃描 PDF（派 subagent）

主 session 不自己讀圖。派一個 `general-purpose`（或 `worker-sonnet`，不改檔）subagent，prompt 給：PDF 路徑、要讀的 PDF 頁範圍、頁碼對照、摘要要抓的五類東西（步驟 3）、輸出格式（Markdown 表、每條標頁碼）。

subagent 內的做法：
```bash
gs -sDEVICE=png16m -r110 -dFirstPage=<n> -dLastPage=<m> \
   -o "$CLAUDE_JOB_DIR/tmp/<前綴>-%02d.png" "<pdf 路徑>"
```
再逐張 Read。一次不超過 20 頁；章節長就分 2–3 個 subagent 平行，各自回傳摘要後由主 session 合併成一份檔。

講義 PPTX／文字 PDF 可直接 Read；有圖片頁（整頁是圖）無法擷取的，在摘要裡註明「p.NN 為圖片，未擷取」，TODO 加「不做」。

## 附錄 B — 常見失誤

- 規劃出已經有的功能 → 步驟 1 沒盤點。
- 任務寫「加強／優化／美化」沒有元件 → 缺口沒寫到元件層。
- 一項任務同時動資料、UI、匯出 → 沒切子任務，worker 會中途停下。
- 子任務各自重抄限制，之後改了一處漏其他 → 限制只寫一次在主任務「已定」。
- 摘要抄書 → 硬規則 3。
- 用 PDF 頁序當書頁 → 步驟 2 第 4 點先核對照。
